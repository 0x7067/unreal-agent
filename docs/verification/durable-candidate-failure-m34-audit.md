## Three different safety boundaries

1. **Preflight, no side effects on A:** bad probe/candidate leaves A alive, unchanged generation, and staging cleaned. This is not proof a trusted probe cannot perform arbitrary I/O, nor proof candidate can decode every persisted session.
2. **After A retires, cannot fall back:** malformed B latches failure, joins B, retains durable admission and does not launch A or retry automatically. Safe stopped recovery after late A retirement requires an explicit request. Do not equate that safe-retirement recovery with authorization to recover a failed-B latch.
3. **After B's first write, cannot downgrade:** the synthetic first-write test proves the stronger unconditional no-fallback policy even after a real committed session append. It does **not** prove a new-format migration or actual older-binary decode compatibility.

## Resident bridge source inspection

Read the new resident runtime control implementation in `cmd/internal/resident/runtime.go` (not a literal file named `newresidentruntime.go`). `startRuntime` delegates replacement solely to `Host.Reload`; it has no rollback path. Completion requires nil error, generation advance and `!stopped`; otherwise stopped status or empty running build yields `state="stopped"` with message “accepted inputs remain durable; no automatic rollback.” Cancellation admission is explicitly not cleanup confirmation. `drainRuntime` retries **only `ErrBusy`**, never a failed candidate or arbitrary error. `cmd/internal/resident/publisher.go` copies `workerhost.Status.Stopped` into attach status. This source mapping supports the intended stopped/no-rollback contract, but is not an observed real-transport failed-B assertion. A `check` reply has a separate ready branch; test stopped-check behavior explicitly if it is to be part of M3.4 acceptance.

## Concrete acceptance gaps / smallest future tests

- **Real resident attach transport failed-B receipt:** exercise real A retirement then candidate startup failure; correlate request/connection; assert final runtime reply is stopped, never completed/ready; status stopped; A and B joined; generation exactly one attempt; old worker never relaunched. Submit an input during the fenced handoff and another after failure: durable admission receipts must not imply delivery, pending entries survive journal reopen, and no false history item appears. Existing tests split these assertions across fake workers and safe-retirement recovery.
- **Compatibility refusal through actual startup:** use immutable unsupported session-header and nested-checkpoint fixtures; compare canonical bytes before/after failed B; assert no provider/environment/operation dispatch, lease release, explicit diagnostic and stopped response if A already retired. Unit decoder refusal and shell byte-preservation are strong components, not end-to-end proof for every format.
- **Supported historical reads:** preserve an actual supported A-produced v2 session plus supported old shell-v3/graph checkpoint fixtures, then read using B and assert history, IDs, versions and uncertainty semantics. Current-code round trips alone do not establish cross-build backward reads. Do not promise v1 session support: it is explicitly rejected.
- **First-write combined failure:** current synthetic test proves real same-format append/no automatic A restart. If M3.4 introduces no format, say so and combine it with stopped reply/durable pending-input assertions. If a genuinely new format is introduced later, add distinct A/B fixture provenance and test B commit followed by failure with no automatic downgrade.
